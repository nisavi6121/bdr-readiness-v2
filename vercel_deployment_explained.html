How the Vercel Deployment Works

git push → live public URL, in ~60 seconds

You don't manage a server. You push to GitHub, Vercel builds your Flask app as a serverless function, and gives you a URL. Here's what's actually happening.

No servers to provision. No clicks. Subsequent pushes redeploy automatically.

1 The runtime model — serverless

The single biggest concept. Vercel doesn't run your app as a long-living server.

Traditional server (Docker / Cloud Run)
  • One Python process always running
  • Port open, listening
  • Already warm — fast responses
  • Costs $ while idle
Serverless (Vercel)
  • No process when no traffic
  • Request arrives → spin up Python, run, return
  • Warm instance reused for next request
  • Idle = $0

Your app works perfectly here because it's read-only and stateless. The DataFrame in module memory survives within a warm instance.

2 What vercel.json tells Vercel
{
  "builds": [{ "src": "app.py", "use": "@vercel/python" }],
  "routes": [{ "src": "/(.*)", "dest": "app.py" }]
}
builds"For app.py, use the @vercel/python builder." Recipe that installs deps from requirements.txt and packages your Flask app as a serverless function.
routes"Send every URL (the (.*) regex catches all) to app.py." Flask then matches its own internal routes (/, /record/<id>, /methodology, /knowledge-base, /guide).
3 The data pre-commit trick

Vercel's filesystem is read-only at runtime, and the pipeline takes too long to run on each cold start. The trick: ship the final CSVs in the repo, gitignore the intermediates.

Committed (rides into the bundle)
  • data/scored/ranked_records.csv
  • data/cleaned/campaign_members.csv
Gitignored (intermediates)
  • data/raw/
  • data/features/
  • data/scored/scored.csv
  • data/cleaned/people.csv

_load() finds the ranked CSV present → skips the pipeline → goes straight to read. Pipeline runs locally; production reads the artifact.

The whole story in one sentence: push to git → Vercel runs @vercel/python to bundle app.py + 4 deps + pre-committed CSVs → every URL routes to your Flask app via the catch-all in vercel.json → cold starts load the CSVs into memory once per warm instance, then every request is just a DataFrame filter.
